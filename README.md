## ✨ Реализованный функционал по чек-листу ТЗ

### 1. Библиотека компонентов и работа с SVG (10 канонических предметов)
- **10 канонических объектов** в двух состояниях детализации (**Размер L** и **Размер S** с коэффициентом `S_SIZE_SCALE_RATIO = 0.65`):
  1. `book` (**Книга**) — раскрытый фолиант;
  2. `phone` (**Смартфон**) — современный телефон с лавандовым стеклом;
  3. `puzzle` (**Пазл**) — две соединяющиеся детали (желтая и розовая) с чистым прозрачным вырезом (`cut-out hole`);
  4. `coin` (**Монета**) — золотой жетон с замком;
  5. `headphones` (**Наушники**) — накладные наушники с белым ободом, лавандовой амбушюрой и золотым диском;
  6. `lamp` (**Лампа**) — высокая настольная лампа;
  7. `vase` (**Букет цветов**) — белая ваза с тюльпанами;
  8. `notebook` (**Кошелек**) — сиреневое портмоне с золотой кнопкой;
  9. `folder` (**Папка**) — папка для документов;
  10. `pen` (**Ручка**) — авторучка с золотым клипом.
- **2 состояния каждого объекта**:
  - `Главный (Main)` — полноцветный акцентный вектор;
  - `Фоновый (Bg)` — монохромный контур/тень.
- Итого **40 чистых векторных SVG-ассетов** (`10 × 2 × 2`, без дубликатов `wallet` и без артефактов обрезки), извлеченных из мастер-слоев Figma.

### 2. Сценарий 1: Сборка по метафоре или заголовку
- Пользователь вводит заголовок статьи или метафору (например: *«Финтех и аналитика»*, *«Глубокий фокус в дедлайн»*, *«Осенний вечер»*, *«Сцена под заголовок»*, а также запросы с падежами и опечатками вроде *«в библиатеками»*).
- Детерминированный парсер [`1-intentParser.ts`](./src/engine/pipeline/1-intentParser.ts) распознает точные пресеты, явные упоминания предметов, тематические корни и опечатки через префиксный Дамерау–Левенштейн (без вызова платных LLM на каждый запрос).

### 3. Сценарий 2: Сборка по списку компонентов и ручной редактор
- Пользователь выбирает нужные компоненты чипсами на отдельной вкладке (полностью изолированной от пресетов метафор) или вводит названия текстом (например: *«кошелек, наушники, букет цветов, ручка»*).
- Алгоритмический резолвер [`2-roleResolver.ts`](./src/engine/pipeline/2-roleResolver.ts) распределяет предметы по изометрическим слоям:
  - **База-подложка** (`book`, `folder`, `notebook`/кошелек) → `zIndex: 2`;
  - **Высокий фон** (`lamp`, `vase`) → `zIndex: 1` (`Bg`);
  - **Главный герой** (`headphones`, `phone`, `puzzle`) → `zIndex: 14–15`;
  - **Акцент / спутник** (`pen`, `coin`) → `zIndex: 8` или `11` с обходом AABB-коллизий.
- В ручном редакторе доступны перетаскивание, поворот на 15°, дублирование, удаление и изменение порядка слоев (`zIndex`).

### 4. Три канонические схемы расположения (Art Director Presets)
1. **«Собранно (Островок)»** — включает точный **«⭐ Эталон арт-директора»**: кошелек (`notebook`, база слева), букет цветов (`vase`, `Bg` в глубине), наушники (`headphones`, `Main` поверх/справа от кошелька) и ручка (`pen`, `Main` на переднем плане).
2. **«Со смещением»** — асимметричный диагональный баланс.
3. **«Под заголовок»** — сдвиг диорамы вправо (`0.28 * W`), освобождающий левую треть полотна под типографику с контролем правой границы (`<= W + 10`).

### 5. Строгое соблюдение пропорций (Закон «НЕЛЬЗЯ»)
- Относительные пропорции предметов зафиксированы в [`CALIBRATED_SCALES`](./src/engine/catalog.ts) под логическую сетку `380×380` и автоматически масштабируются при смене формата (`1:1`, `16:9`, `9:16`) и переключении детализации `L` / `S` (`S_SIZE_SCALE_RATIO = 0.65`).
- Ручное изменение масштаба отдельного объекта в инспекторе холста заблокировано, чтобы не нарушать пропорции между элементами сцены.

### 6. Работа с цветовой палитрой и кастомный импорт
- 3 встроенные палитры: **Lavender** (`#D7CDF5`), **Sand & Peach** (`#FDD7B9`), **Mint & Teal** (`#BEEBEB`) + импорт пользовательской JSON-палитры.
- **Правило дизайн-системы:** *«Цвета фонов могут использоваться в объектах. Цвета для объектов не могут использоваться в фонах»* — строго контролируется валидатором `isAllowedCanvasBg()`.

### 7. Экспорт чистого векторного SVG
- Скачивание автономного векторного SVG без растра в 1 клик (`Скачать SVG`) с сохранением слоев, групп и векторных путей.

### Хранение, извлечение и переиспользование SVG
1. **Хранение (Storage):** Все 40 SVG-ассетов очищены от лишних артбордов и растра. Vite компилирует их в память на этапе сборки через `import.meta.glob('/src/assets/illustrations/*.svg', { query: '?raw', eager: true })`, исключая лишние HTTP-запросы.
2. **Извлечение и скоупинг (Retrieval & Scoping):** Функция `getRawSvg(id, size, variant)` мгновенно возвращает исходный вектор. Чтобы при дублировании объектов на холсте не конфликтовали внутренние маски и градиенты, [`scopeSvgIds()`](./src/engine/pipeline/4-svgCompiler.ts) изолирует все `id="..."`, `url(#...)` и `href="#..."` уникальным префиксом `instanceId`.
3. **Перекраска (Recolor):** [`recolorSvgPure()`](./src/engine/pipeline/4-svgCompiler.ts) за один проход сопоставляет заливки (`fill`) и обводки (`stroke`) с ролями активной палитры без искажения геометрии.
4. **Сборка (Assembly):** [`compileFullSvg()`](./src/engine/pipeline/4-svgCompiler.ts) и `assembleFullSvg()` формируют валидный XML SVG-документ, сортируя `<g transform="...">` по `zIndex` (алгоритм художника).

## 🧪 Качество, тесты и Debug Inspector

- **Vitest (`npm test`):** **78 тестов** (покрывают `1-intentParser` включая склонения и опечатки, `3-spatialPlacer` включая AABB-коллизии и детерминизм по `seed`, `4-svgCompiler` и `smokeSuite`).
- **Smoke Suite (`npm run smoke`):** **21 встроенный инвариант** (работает в CLI, REST API и прямо в UI).
- **Zero-DOM проверка (`npm run typecheck`):** запускает `tsc --noEmit` отдельно для браузера (`tsconfig.json`) и для Node без `DOM` ([`tsconfig.node.json`](./tsconfig.node.json)) — любая случайная ссылка на `window` или `document` внутри `src/engine/` заблокируется компилятором.
- **Headless CLI и HTTP API (`scripts/compose-cli.ts`, `vite.config.ts`):**
  - `npm run compose -- --prompt "библиатека" --out scene.svg`
  - `npm run serve:api` / Vite dev-middleware: `GET /api/health`, `GET /api/smoke`, `POST /api/compose`.
- **Debug Inspector (`Ctrl + Shift + D`):** встроенная панель разработчика в UI с просмотром `PipelineTrace`, AABB-оверлеем на холсте, живым запуском `smokeSuite` и выгрузкой Debug Bundle в JSON.

## 🤖 Использованные AI-инструменты

В разработке использовался мультиагентный стек моделей:
1. **Google Antigravity (Gemini 3.8 Flash)** — оркестрация задач, автоматизация парсинга и live E2E-тестирование в браузере через Browser Bridge.
2. **Claude Opus 5.5** (`run-aider.ps1` / `ask-ai.py`) — проектирование и рефакторинг Zero-DOM доменного ядра `src/engine/`, Headless CLI/API и финальное третейское ревью.
3. **Claude Sonnet 5.5** — разработка React-компонентов (`AiModal`, `DebugInspectorModal`, калибровка эталона, префиксный Дамерау–Левенштейн), чистка векторных масок SVG и написание тестов.
4. **Google Gemini 4 Carbon** — аудит архитектуры, безопасности HTTP API, анализ дампа Figma (840 КБ SVG) и верификация контрактов.
5. **DeepSeek R1** — математический и инвариантный аудит AABB-коллизий, весовой нормализации и границ композиции.
6. **Claude Fable 5.2** — арт-дирекшн аудит пропорций элементов и изометрической иерархии слоёв.

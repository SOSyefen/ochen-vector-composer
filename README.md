### Пайплайн из 4 стадий

```
 Вход (метафора / список)
        │
        ▼
 ┌────────────────┐   ┌────────────────┐   ┌─────────────────┐   ┌────────────────┐
 │ 1-intentParser │──▶│ 2-roleResolver │──▶│ 3-spatialPlacer │──▶│ 4-svgCompiler  │──▶ SVG
 └────────────────┘   └────────────────┘   └─────────────────┘   └────────────────┘
        │                    │                     │                     │
        └────────────────────┴──────── traceStore ─┴─────────────────────┘
```

| Стадия | Ответственность |
|---|---|
| `1-intentParser` | Разбор метафоры/заголовка и текстового списка компонентов, нормализация названий предметов |
| `2-roleResolver` | Назначение ролей (база, высокий фон, герой, акцент), `layerTier`, состояний Main/Bg |
| `3-spatialPlacer` | Применение схемы арт-директора, расчет координат, масштабов (с учетом размера L/S и формата холста), `zIndex` |
| `4-svgCompiler` | Сборка автономного SVG: слои, группировка, трансформации, перекраска по палитре |

Каждая стадия пишет трассу в `traceStore` (время по инжектируемым часам из `clock`). Эти данные использует Debug Inspector и REST-эндпоинты.

### Хранение, извлечение и переиспользование SVG
1. **Хранение (Storage):** SVG-файлы хранятся как чистые векторные пути. Vite компилирует их в единый бандл через `import.meta.glob(..., { query: '?raw', eager: true })`, без сетевых задержек и лишних запросов.
2. **Извлечение (Retrieval):** `getRawSvg(id, size, variant)` возвращает исходный вектор нужного размера и состояния.
3. **Перекраска (Recolor):** `recolorSvg()` сопоставляет заливки (`fill`) и обводки (`stroke`) с семантическими ролями палитры без деформации геометрии.
4. **Сборка (Assembly):** стадия `4-svgCompiler` генерирует чистый XML SVG-документ с правильным порядком слоев по алгоритму художника (`zIndex`).

## 🧪 Качество и верификация

### Тесты (Vitest)

```bash
npm test            # однократный прогон: 61 тест
npm run test:watch  # режим наблюдения
```

Набор из **61 теста** покрывает стадии пайплайна, пресеты арт-директора, правила палитры, масштабирование L/S и сквозную компиляцию SVG. Движок не зависит от DOM, поэтому тесты идут без браузерного окружения и с детерминированными часами.

### Строгая Zero-DOM проверка компиляции

```bash
npm run typecheck   # tsc --noEmit && tsc --noEmit -p tsconfig.node.json
```

- `tsconfig.json` проверяет UI-слой.
- `tsconfig.node.json` компилирует `src/engine/` и `scripts/` в строгом режиме без DOM-окружения. Любое обращение к `window`, `document` или другим браузерным API внутри движка приводит к ошибке компиляции. Это гарантирует, что ядро остается переносимым.
- `npm run build` запускает ту же проверку до `vite build`.

## 🖥️ Headless CLI и REST API

Движок работает без браузера через единый entrypoint `scripts/compose-cli.ts`:

| Команда | Назначение |
|---|---|
| `npm run compose` | Headless-сборка иллюстрации через CLI (результат — векторный SVG) |
| `npm run smoke` | Прогон встроенного smoke-набора (`smokeSuite`) с отчетом о прохождении |
| `npm run serve:api` | Запуск REST API поверх того же движка |

### HTTP-эндпоинты (`npm run serve:api`)

| Эндпоинт | Назначение |
|---|---|
| `/api/health` | Проверка живости сервиса |
| `/api/smoke` | Запуск smoke-набора и возврат результата |
| `/api/compose` | Сборка композиции: принимает запрос по контрактам `src/engine/contracts`, возвращает результат компиляции и трассу пайплайна |

CLI и API используют те же функции `compose()` и `4-svgCompiler`, что и веб-интерфейс, поэтому результат идентичен во всех трех режимах.

## 🔍 Debug Inspector (в приложении)

Встроенная панель отладки открывается по **`Ctrl + Shift + D`**:

- **AABB-оверлей на холсте** — ограничивающие прямоугольники (axis-aligned bounding box) каждого объекта поверх сцены. Помогает проверять пересечения, выходы за границы и точность раскладки.
- **Трасса пайплайна** — результаты и тайминги стадий 1–4 из `traceStore`.
- **Debug Bundle (JSON)** — выгрузка в один файл состояния сцены и трассы выполнения для воспроизведения и разбора проблем.

- **Вкладка 2:** выбор компонентов развязан с состоянием вкладки 1, и взаимная перезапись исключена.

- **Архитектура:** логика сборки вынесена в Zero-DOM `src/engine/`, добавлены тесты, строгая проверка компиляции, CLI/REST и Debug Inspector.
